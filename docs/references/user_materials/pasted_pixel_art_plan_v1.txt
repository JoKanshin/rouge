# 灰烬之下 AI 像素美术素材制作方案

版本：1.0 · 2026 年 10 月 26 日

本方案面向已完成的 A 阶段战斗试验场，规划第一批能进入 Godot 的像素素材。先让巡灯人、三类敌人和废矿训练室呈现统一风格，再扩展城镇、遗物和 Boss。本文交付的是制作规格、资产清单、生成提示词与验收流程，本轮尚未生成正式美术素材。

**制作原则：先做一张通过游戏实景验证的风格样板，再用它约束整套素材。生成图只是候选，最终交付要满足真实尺寸、透明通道、锚点、动作时序和游戏可读性。**

## 1 视觉目标

### 1.1 暖灯冷矿

整体为冷色废矿与温暖火灯形成的对比：旧铁、石墙、木梁、矿尘，配少量铜色与余火。角色以清楚的灰白头部、青灰护衣、短铜红披巾和腰灯形成识别。背景压低对比，危险通过动作轮廓和橘红强调，灯焰技能使用浅青色。

巡灯人的识别点是“方形旧铁面罩 + 短披巾 + 腰侧矿灯 + 单手直剑”。所有敌人也要有一眼能分辨的轮廓：矿工宽肩与举镐，弩手瘦长与水平弩，飞蝠展开的翼形。先保证缩成剪影仍能识别，再加金属、皮革和布料的少量纹理。

《空洞骑士》用于参考角色与背景分层、危险可读性；《死亡细胞》用于参考动作姿态和效果层级；《赛菲莉娅》用于参考装备图标与组合信息如何被清楚展示。最终世界观、角色、图标、配色组合和场景构成使用本项目设计，不直接使用这些游戏的成品素材。

### 1.2 风格约束

- 侧视横版，相机平视，不出现俯视地板、等角角色或透视缩短的行走动画。
- 统一逻辑像素尺度。地形以 16×16 为基础；人体有效高度接近现有 28 像素受击体，而不是把细节丰富的大角色强行缩进场景。
- 硬像素边缘、有限色阶、清楚的大块形体；不用高分辨率插画铺一层像素滤镜冒充最终素材。
- 角色主体每种材质通常使用 2–3 阶明暗。避免大量孤立亮点、密集抖色、空气笔渐变与体积光。
- 主光方向统一为左上环境光；灯具可在独立效果层产生局部亮点。角色转向时可接受像素游戏常用的整体镜像，腰灯需要保持在角色设定的同一侧时再补独立层。
- 文字、数值和按键提示由引擎绘制；图标图片不含文字。危险预警优先保持现有程序图形，保证位置与时序准确。

## 2 调色板与尺度

### 2.1 基准色表

先以现有游戏中的颜色作为候选色板，样板通过后固定版本。16 个基础色加 2 个效果强调色，按素材类型选子集，不要求每张图用满色表。

| 用途 | 色值 |
| --- | --- |
| 最深背景 / 背景 | #0D151D / #111922 |
| 远景石块 / 前景石块 | #17232D / #29383E |
| 石材中间色 / 石边亮面 | #3C4A4C / #72817B |
| 青灰护衣 / 灰白主体 | #83AAA9 / #D5DACF |
| 剑刃和短促高光 / 暖黄 | #FFF0C9 / #DFBF85 |
| 铜色 / 木色 | #C49C63 / #806B52 |
| 披巾 / 受伤低饱和红 | #C98668 / #B77C73 |
| 敌人起手强调 / 飞蝠辅色 | #EFAB79 / #A69AC2 |
| 灯焰技能 / 高危险强调 | #8BD2C5 / #F0776C |

每个角色优先控制在约 8–12 个实色。普通主体 PNG 使用硬透明边缘，半透明保留给烟、刀光和火焰等独立效果。AI 输出不保证准确遵守十六进制色表，需在最终像素整理时核对。

### 2.2 资产尺寸和锚点

下表是**最终进入游戏的逻辑分辨率**，不是要求图像生成工具原生输出这些小尺寸。生成阶段可以较大画布探索造型，最终必须整理到规定格子；不能把模糊缩小图直接当作交付。

| 资产 | 单帧画布 | 位置基准 | 说明 |
| --- | --- | --- | --- |
| 巡灯人身体 | 32×48 | 脚底锚点 (16, 44) | 站立有效主体约 14×28；剑与长刀光分层 |
| 剑与招式效果 | 96×96 | 对齐角色脚底的锚点 (32, 64) | 预留上挑、下劈、横斩轨迹；默认朝右 |
| 矿工 | 64×64 | 脚底锚点 (24, 56) | 预留举镐与武器外伸 |
| 弩手 | 48×48 | 脚底锚点 (16, 44) | 高位与低位持弩姿势分开 |
| 飞蝠 | 64×48 | 身体底部锚点 (32, 36) | 翼展不能挤出画布；与地面脚底概念区分 |
| 地形格 | 16×16 | 左上角 | 单独 PNG 起步，验证后再打包图集 |
| 道具 / 灯具 / 宝箱 | 16×16、32×32 或 32×48 | 左上或地面锚点，逐项记录 | 画布大小必须是项目约定的整数格 |
| 遗物和武器图标 | 24×24 | 图标中心 (12, 12) | 独立透明图，可在 UI 中整数倍显示 |
| 远、中景模块 | 320×160 或 320×240 | 左上角 | 标注是否横向循环，不能假定任意图都可无缝拼接 |

所有动画帧保留完整画布，不逐帧裁成不同大小。身体与剑层通过各自锚点对齐同一游戏原点；不能用纹理外框自动生成角色受击框。只有确有需要时才改变画布规格，变更后同步改资产清单。

## 3 分批素材清单

### 3.1 P0 风格验证包

先完成以下 8 个交付项，装入当前训练场验证后再扩量：

1. 风格母板 1 张：巡灯人、三类敌人、石墙、木梁、火灯与色板并排呈现，用来比较统一尺度和材质。它不是可直接切图的生产图集。
2. 巡灯人站立主帧 1 张：朝右、透明背景、锚点与当前角色对齐。
3. 巡灯人第一刀的预备、接触、收招 3 个姿态：验证身体与剑层能否保持造型和尺度。
4. 矿工正常与举镐 2 个姿态：验证危险预警在原尺寸能否辨认。
5. 飞蝠展翼和收翼 2 个姿态：验证空中单位轮廓。
6. 石台样块：16×16 地面上沿、填充、边缘和平台各一格。
7. 矿灯道具 1 张：验证暖色焦点不过亮。
8. 游戏实景样板 1 张：把候选角色与地形放进实际训练场截图比较，记录通过/退回原因。

P0 不能仅凭独立大图“看起来精致”通过。必须在 1× 逻辑尺寸和 2× 游戏窗口下观察：敌我是否混在一起、剑是否覆盖真正命中位置、举镐是否明显，以及背景是否抢眼。

### 3.2 P1 A 阶段完整替换包

| 类别 | 动画或素材 | 建议独立帧数 |
| --- | --- | --- |
| 玩家基础动作 | 待机 4、跑步 6、起跳 1、下落 1、落地 2、下蹲 1、冲刺 2、受击 2、倒下 4 | 23 |
| 玩家剑术动作 | 轻击 1/2/3 各 5、上挑 4、下劈 4、重击 6、灯焰 4、喝药 4 | 37 |
| 矿工 | 待机 2、走路 4、预警 3、攻击 3、恢复 2、受击 1、倒下 3 | 18 |
| 弩手 | 待机 2、走路 4、瞄准 3、发射 2、装填 3、受击 1、倒下 3 | 18 |
| 飞蝠 | 盘旋 4、收翼 2、俯冲 2、恢复 2、受击 1、消散 3 | 14 |
| 训练场 | 16 个结构地形格、8 个装饰地形格 | 24 格 |
| 场景道具 | 木桩、矿灯、锁链、木梁、门框、矿箱、标牌、碎石 | 8 类 |
| 背景 | 远景矿壁、中景拱架、近景遮挡模块 | 3 层 |
| 效果 | 普攻刀光、重击刀光、灯焰环、接触火花、破势、灰尘 | 6 组 |

这对应约 110 个角色动作帧，左右镜像不额外计数，也不等于 110 次 AI 调用。先为每个动作生成少量关键姿态，再用像素编辑与有限补帧完成连续性；披巾摆动、烟尘、震动和命中闪烁优先沿用引擎实现。初版可复用一些受击与恢复姿态，逐项记录复用，避免为了帧数重复无意义画面。

### 3.3 P2 后续扩展包

待随机地牢和构筑验证后再制作：食堂与铁铺外观、城镇 NPC、另三类敌人、矿炉监工与三种核心攻击、12 件遗物图标、2 种灯匣刻印，以及普通/精英/商店/篝火/Boss 门的功能识别物。

Boss 先锁轮廓与预警姿态，再补细节；遗物先确认游戏效果与名称，再生成图标。不要提前批量画尚未确定的武器或几十张不能实际使用的装备图。

## 4 AI 生成与整理流程

### 步骤一 建立素材卡

每次生成对应一个明确任务：资产 ID、用途、参考图角色、最终尺寸、朝向、锚点、状态、允许改变项、必须保持项、输出背景与验收点。参考图分别标为造型、色板、姿态或游戏比例，不把某一张游戏截图里的所有物体都当成必须生成的内容。

### 步骤二 选定造型母版

先为巡灯人产出少量候选，通过原尺寸识别性选择一个。保留朝右标准姿态、色板与角色局部细节作为母版；后续矿工、弩手、蝠和道具使用同一母板约束尺度、光线与纹理密度。

### 步骤三 每个动作先做关键姿态

按预备、接触、收招逐个处理，同一次只要求改变一个明确姿态。连续参考上一张通过的主帧，固定头身比、服装、配件和光线。整张动画图集可以作为草稿，但不能未经核对就用自动平均切格上线。

角色转向先镜像，确有明显左右差异时再补帧。跑步循环先检查脚的接地和回环，剑术先检查攻击方向与轨迹，飞蝠先检查收翼预警和展开俯冲的差别。

### 步骤四 像素整理

在像素编辑器中按最终画布整理轮廓、颜色与锚点，清除伪透明棋盘、抗锯齿边缘、孤立噪点和多余高光。用最近邻预览放大检查像素结构，在深色、浅色和高对比背景上检查透明边缘。

AI 改图使用图像编辑能力保持主角身份；逐像素修整、精确排帧和锚点定位由像素编辑流程完成。生成工具的“像素风”提示本身不能保证动画中每一个像素、肢体和装备位置一致。

### 步骤五 检查和打包

先输出独立帧 PNG 和动作元数据，再按固定格子打包。检查尺寸、透明通道、边界溢出、脚底锚点、颜色数、循环首尾和空白帧。图集是否加间隔取决于导入方式，打包时写入格子尺寸和间隔，不能让运行时猜测切分。

### 步骤六 装进实际游戏

先替换站立、跑步和轻击第一段，保持现有移动、攻击时序、碰撞体和伤害判定。确认人物不漂浮、剑轨迹与命中区域吻合、遮挡关系正确，再替换其余动作与场景。每一批都保存游戏实景截图和一段动作回放。

默认生成与改图按当前可用的内置图像生成流程执行，透明素材明确要求真正的透明背景。项目使用的最终文件复制进项目资产目录，保留版本号；原始候选不直接覆盖已验收素材。不预设 API 密钥、付费 API 批处理或模型切换；若将来选择这些路径，再根据实际工具条件单独配置。

## 5 可直接使用的生成提示词

以下为任务模板。`[母版]`、`[姿态参考]` 等标记需替换为实际参考图，并明确其角色；尺寸表示最终资产目标，导出规格仍要通过整理和检查保证。

### 5.1 巡灯人主帧

```text
用途：Godot 2D 横版动作游戏《灰烬之下》的玩家角色标准主帧。
主体：原创巡灯人，旧铁方形面罩，青灰护衣，短铜红披巾，腰侧暖黄矿灯，单手直剑。沉默的矿道探索者，朴素、轻便，轮廓清楚。
视角：严格侧视，朝右站立，平视相机。不要俯视、等角或三维透视。
风格：低分辨率像素角色，大块清楚的像素轮廓，有限色阶，无平滑渐变、无抗锯齿、无摄影纹理。
比例：最终身体画布 32×48，脚底锚点 (16,44)，有效站立主体约 14×28。剑可单独交付，不能挤压身体比例。
色彩：深蓝灰阴影、灰白头部、青灰护衣、铜红披巾、暖黄小灯。只让腰灯产生小面积亮点。
构图：一个角色，四周留出透明安全边距，脚底水平，不含地面投影、文字、边框或其他角色。背景真正透明。
验收重点：在原尺寸仍能认出面罩、披巾与矿灯，头和武器不融在一起。
```

### 5.2 单个动作关键帧

```text
任务：基于附图巡灯人母版，生成“第一段横斩的接触姿态”。
输入图角色：图 1 是身份和色板母版；图 2 如有，仅是姿态参考。
只改变：肩、手臂、身体重心和剑的位置，使剑向角色右侧横向切出。
保持：面罩形状、头身比、服装、灯的位置、配色、像素密度、光线方向及侧视角度。
脚底锚点不移动。身体维持 32×48 格子，剑与刀光使用独立效果层，目标画布 96×96，脚底参照点 (32,64)。不要把刀光画进身体轮廓，不要添加第二把剑或额外肢体。
真实透明背景。不要生成动作说明文字，也不要自行排成多帧图集。
```

### 5.3 矿工预警姿态

```text
任务：为同一游戏制作原创镐斧矿工，当前状态是“下砸前举镐蓄力”。
参考：[已通过的矿工标准姿态] 负责角色身份；[风格母板] 负责像素尺度、材质和颜色。
严格侧视朝左。矿工身体宽厚，短粗外套，旧矿帽，双手把镐举到头部上方，身体有清楚的蓄力弯曲。武器举起的剪影要与正常走路明显不同。
保持标准姿态的服装、头身比和光线，使用灰棕矿工配色与少量暖黄帽灯。不要靠整个人变红表示预警；危险标记由引擎绘制。
最终画布 64×64，脚底锚点 (24,56)，脚底与标准帧对齐，武器不能出框。真正透明背景，无文字，无背景，无其他人物。
```

### 5.4 地形与接缝

```text
用途：16×16 基础格的侧视废矿地形，供 Godot 平台碰撞区域使用。
先制作一个石质平台顶面样块：上边沿清楚、可站立面水平，正面为深蓝灰石材，有少量压暗的裂纹与旧木支撑。不要俯视地板透视。
色彩和明暗匹配附图风格母板。平台上边沿要比背景亮，但不要比玩家的灰白面罩亮。纹理保持大块、有节奏，避免密集噪点。
明确交付角色：这是地形样块，不是完整游戏截图，也不是可直接上线的自动拼接图集。不要画角色、文字、灯光光晕或 UI。
后续基于该样块制作左右边缘、填充和底边，逐项检查它们实际并排后的接缝。
```

### 5.5 遗物图标与灯匣刻印

```text
用途：横版动作肉鸽的装备图标，最终 24×24。
对象：穿火针，一枚带铜色穿孔结构的旧矿钉，针尖方向清楚，局部留一条浅青余热线，表达“冲刺后首刀刺击”。
风格：同一套有限色板、硬像素边缘、少量明暗块面。在 24×24 原尺寸辨识；图案不能只依赖发光或复杂花纹。
一个物品，居中，透明背景，不含名称、数字、品质边框、字母或水印。品质和是否被刻印强化由引擎额外绘制。
```

## 6 动画时序与战斗判定对齐

美术帧数和物理帧数是两个概念。轻击第一段 5 帧前摇、4 帧有效段、9 帧后摇是 60 Hz 的战斗时间，不是要求画 18 张不同图。

可将 5 张美术帧分为预备 2、接触 1、收招 2，并分别安排在上述时间段。攻击区域继续由战斗数据启用，不能因为刀光还没播完就延长伤害，也不能让接触姿态明显晚于真正扣血。

受击闪烁、冲刺残影、镜头震动和伤害数字沿用程序实现。动画节点只控制视觉，不移动 CharacterBody2D，不把披巾或刀光透明外框纳入身体碰撞。下蹲姿态必须符合已缩小的受击区域，上挑与下劈的剑尖应进入对应的伤害区域。

## 7 Godot 接入方式

1. 保持 640×400 逻辑分辨率、viewport 拉伸与整数倍缩放；不同窗口比例允许留边，避免像素非等比拉宽。
2. 主体纹理选择无损压缩、Nearest 过滤，关闭不需要的 mipmaps；分别检查 UI 和粒子是否继承了正确过滤方式。Godot 4 的过滤主要由 CanvasItem 或项目设置控制，不把旧版本导入选项位置当成通用规则。
3. 玩家添加 Visual 子节点管理身体和剑层，通过元数据锚点对齐；身体逐帧画布固定。角色转向只影响视觉朝向，不整体翻转碰撞与判定系统。
4. 可用 AnimatedSprite2D / SpriteFrames 管理循环动作，剑术与预警通过 AnimationPlayer 或现有战斗时钟显式选择美术帧。现有战斗逻辑是时序权威，接图时不重复启动一套伤害时钟。
5. 地形先用独立格子构建 TileSet，再核对碰撞与单向平台属性；背景装饰不自动带碰撞。可走边缘与受击危险区仍需人工定义。
6. 每次整合后回跑战斗检查和关键跳跃，确认换图没有改变角色可达性、下蹲高度和出招窗口。

实现依据：[Godot 图像导入](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html)、[2D 动画](https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html)、[分辨率与缩放](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)。具体设置以项目正在使用的 Godot 4.7.2 导入面板和运行结果核对。

## 9 验收与返工规则

| 检查项 | 通过条件 | 常见退回原因 |
| --- | --- | --- |
| 风格 | 与风格母板同像素尺度、视角、颜色和细节密度 | 单张精细但角色像从另一款游戏搬来 |
| 轮廓 | 原尺寸区分主角、矿工、弩手、飞蝠 | 敌我颜色和头部形状过于接近 |
| 技术 | 真透明、正确尺寸、无出框、非空帧 | 棋盘底画进图片，镐尖被切掉 |
| 动画 | 锚点稳定、装备不漂移、首尾能循环 | 跑步时头变大，腰灯换边，脚底上下跳 |
| 战斗 | 预警可读、接触帧与实际伤害一致 | 刀未到人先扣血，爆光盖住下一招 |
| 地形 | 上边沿清楚，接缝可接受，碰撞不含装饰 | 看起来能站却会掉下去 |
| 效果 | 重要性分级，关闭闪光仍可辨识命中 | 每一刀整屏闪白、火焰淹没敌人 |
| 游戏实景 | 1×、2×、移动中和受击中都能读懂 | 只看放大静态图，不看游戏 |

同一素材连续两轮修图仍无法保持身份或动作比例时，回到标准主帧，缩小任务，只修一个关键姿态。不要反复给整套图集追加要求，导致所有已合格帧一起漂移。

## 10 执行顺序与完成定义

**第一批只做 P0。** 先确定巡灯人主帧、第一刀、矿工举镐与一段平台的游戏实景。角色、敌人、地形三者同时成立，才进入 P1。

P1 先替换玩家与三类敌人的关键动作，再做循环补帧、场景与效果。P2 随对应玩法阶段推进。制作量以通过的资产包计算，不以生成图片数量计算，也不预先承诺所有动画一轮生成成功。

美术替换完成的定义是：资产可在项目内追溯、动作与判定同步、关键规则检查仍通过，并打开最新游戏验证真实场景。最终应交付正式 PNG、动作配置、可编辑源文件、提示词与参考记录，以及实景验收截图。
